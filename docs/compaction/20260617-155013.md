# Session Compaction - Type Key Universal Permissions (Tasks 1-8 Complete)

## Goal
Refactor permissions architecture to align with CTI pattern, unifying relationship/object ownership and implementing data-driven `type_key` routing middleware.

## Constraints & Preferences
- Strictly follow `docs/workflow.md` plan/template format for progress tracking
- No double implementation or scope creep; handlers/routes remain manual per type
- `type_key` column on `object_types` must be required (never empty)
- Remove relationship-specific 3-tier ownership models; use single unified model (`created_by == userID`)
- Endpoint ownership validation moved to service-layer business logic, not permission layer
- Replace hardcoded middleware strings with data-driven `RouteConfig{TypeKey, HTTPMethod}`
- No dynamic URL generation or universal type-specific handlers
- Object types implementation stays as-is (separate table, separate routes)

## Key Decisions
- CTI establishes "Relationship IS an Object"; permissions logic must no longer treat them as fundamentally different domains
- All ownership checks collapse into one: `created_by == userID`; endpoint validation for relationship creation becomes service-layer business rule
- Middleware refactored entirely (`permissionMiddleware` function replaces old implementation); no backward compatibility needed (service not in prod)
- Route groups remain manual per type; only permission string construction becomes dynamic based on `RouteConfig{TypeKey, HTTPMethod}`
- `/api/v1/object-types/*` routes use hardcoded multi-permission checks (registry table operations, no ObjectType row exists for `"Objects"` or `"object-types"`)
- Shared handler utilities in `base.go` avoid code duplication; no inheritance/embedding pattern used — package-level functions are cleaner

## Critical Context
- Current architecture doc contradicts CTI data model by giving relationships a separate namespace and three distinct ownership models
- Hardcoded permission strings in routes (e.g., `"relationships:create"`) mismatch scoped DB values (`:own`/`:all`), causing all relationship endpoints to return 403
- Object.List lacked `created_by` filtering for `:own` scope, leaking all objects to users with minimal permissions — fixed via Task 7 repo-level filter
- Relationship handler never assigned `CreatedBy`, defaulting to `"system"` — fixed in Task 6
- `handleServiceError` used exact comparison (`==`) instead of `errors.Is()`, misrouting repository errors as 500 — fixed in Tasks 6+8
